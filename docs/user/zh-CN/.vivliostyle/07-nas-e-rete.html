第 7 章：NAS、网络磁盘与 SMB 路径

7.1 为何网络磁盘需要特殊处理

大多数桌面下载应用程序能正确处理本地路径（C:\、D:\），但当目标是 NAS、共享 Windows 服务器或 SMB 驱动器时，行为往往不可预测。原因是技术性的：网络磁盘本质上不如本地磁盘可靠。NAS 可能已关机，局域网可能出现延迟峰值，SMB 凭据可能过期。任何对无响应的网络路径的操作都可能将应用程序的主线程阻塞数十秒，导致界面失去响应。

FeedDownloader Pro 能正确处理这些情况。对于在 NAS 上归档的用户，本章至关重要。

7.2 网络路径验证的工作方式

每当设置的目标路径以 \\（UNC 路径，典型的 SMB 格式）开头，或对应映射的网络驱动器（例如 Z:\）时，FeedDownloader Pro 会自动激活网络路径验证模块。

此模块在独立线程上执行三项操作，完全不涉及界面线程：

  1. 可达性测试： 尝试访问网络路径的根目录。如果 NAS 未开机或网络不可用，此操作将失败。
  2. 读取权限测试： 验证目标文件夹存在且可读。
  3. 写入权限测试： 在目标文件夹中创建并删除一个临时文件（_fdp_write_test_[时间戳].tmp），以验证写入权限。

整个序列的超时时间为 8 秒。如果在此时间内未收到响应，软件将认为路径不可用并显示警告，而不会阻塞界面。

超时时间的设定依据： 大多数消费级 NAS（Synology、QNAP、WD MyCloud）从休眠模式唤醒需要 3–6 秒。8 秒的时间足够等待此恢复过程，同时对用户来说足够短，不会感觉是明显的等待。

7.3 配置 NAS 路径

方法 1——直接 UNC 路径： 以 \\服务器名\共享名\文件夹 格式输入路径： 

\\MYNAS\Podcast\Archivio
\\192.168.1.100\media\podcast
\\NAS-SYNOLOGY\video\audio_archive

路径可以直接输入到目标文本字段中，也可以通过文件夹选择窗口输入，Windows 上的该窗口支持浏览网络路径。

方法 2——映射网络驱动器： 如果 NAS 已在 Windows 中映射为网络驱动器（例如 Z: → \\MYNAS\Podcast），可以选择 Z:\Archivio 作为目标文件夹。FeedDownloader Pro 会自动识别这是网络路径并激活验证。

方法 3——macOS 和 Linux（挂载点）： 在 macOS 和 Linux 上，SMB 网络路径在挂载后作为普通文件夹呈现在文件系统中（macOS 上例如 /Volumes/MYNAS/Podcast，Linux 上例如 /mnt/nas/podcast）。这些路径可以直接用作目标文件夹。

7.4 SMB 凭据与身份验证

NAS 的访问凭据必须在操作系统级别配置，而非在 FeedDownloader Pro 内部配置。

在 Windows 上：

  1. 打开文件资源管理器，导航至 NAS 路径（\\MYNAS\）。
  2. 在提示时输入凭据，勾选"记住我的凭据"。
  3. 凭据将保存在 Windows 凭据管理器中（控制面板 → 凭据管理器 → Windows 凭据）。
  4. FeedDownloader Pro 与任何其他应用程序一样，无需额外凭据即可访问 NAS。

在 macOS 上： 挂载共享时会提示输入 SMB 凭据（在 Finder 中：前往 → 连接服务器 → smb://192.168.1.100/共享名）。macOS 将其存储在钥匙串中。

在 Linux 上： 通过 fstab 文件或 GNOME Files 等图形工具使用凭据挂载共享。或者从终端使用 smbclient 或 mount -t cifs。

7.5 网络路径问题诊断

如果出现"网络路径不可访问"警告，请按以下顺序检查各项。

1. NAS 是否已开机并启动完成？ 检查设备指示灯。许多消费级 NAS 在一段时间不活动后会进入休眠模式。在开始下载前，从浏览器打开 NAS 管理面板以确认其可用性。

2. NAS 是否可通过网络访问？ 从命令提示符（Windows）或终端（macOS/Linux）执行： ping 192.168.1.100 将 IP 地址替换为 NAS 的实际地址。如果命令收到响应，说明基本网络连接正常。

3. SMB 共享是否可访问？ 尝试直接在 Windows 文件资源管理器中打开路径 \\192.168.1.100\共享名。如果操作失败，问题在于 NAS 的 SMB 配置，而非 FeedDownloader Pro。

4. 写入权限是否正确？ 通过文件管理器手动在目标文件夹中创建一个文件。如果操作不被允许，用于访问 NAS 的用户在该共享上没有写入权限。请从 NAS 管理面板配置权限。

5. 防火墙是否阻止了 SMB 连接？ SMB 协议使用端口 445（某些情况下还使用端口 139）。请确认系统防火墙或第三方防火墙未阻止局域网上这些端口的连接。

7.6 在 NAS 上获得最佳性能

在 NAS 上下载比在本地磁盘上下载有额外的复杂性：文件通过网络写入，速度取决于局域网带宽和 NAS 的写入能力。

操作建议：

  • 使用有线连接（Ethernet）： Wi-Fi 会为网络写入操作引入延迟和不稳定性。对于大型存档，有线千兆以太网连接提供明显更好的性能。
  • 减少并行线程数： 同时向 NAS 写入多个文件可能使其 I/O 饱和。通常 2–3 个并行线程比使用最大可用数量效果更好。
  • 避免与 NAS 备份重叠： 如果 NAS 执行自动备份，请避免在相同时间窗口内启动批量下载，因为磁盘 I/O 竞争会降低两者的速度。
  • 使用本地缓存： 对于非常大的存档，可以先下载到快速本地磁盘，在下载完成后再将文件移至 NAS。
