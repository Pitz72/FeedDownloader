第 8 章：文件组织、模板与元数据

8.1 无意义文件名的问题

音频文件发布到播客服务器时，其原始名称通常可读性很差：ep_2024_03_15_FINALE_v2_mixdown.mp3、podcast-episode-187-compressed.m4a，甚至只是 abc123def456.mp3，这些都是常见例子。这些名称对制作方的系统有意义，但会让存档难以查阅。

FeedDownloader Pro 通过重命名模板系统解决这一问题：该机制允许为所有已下载文件定义自定义名称格式，使用直接从 RSS feed 提取的信息。

8.2 模板的工作方式

重命名模板是一个文本字符串，可以包含固定文本和令牌——用单个花括号（{ }）括起来的变量。每次下载完成后，软件将每个令牌替换为对应节目的值。

示例：

配置的模板：{date} - {podcast} - {title}

结果：2024-03-15 - 马里奥播客 - 第 187 集：人工智能通俗解读.mp3

文件扩展名（.mp3、.m4a 等）根据原始文件格式自动添加，不是模板的一部分。

8.3 可用令牌

令牌 说明 示例
{title} RSS feed 中的节目标题 第 187 集：人工智能通俗解读
{podcast} 播客名称（RSS 频道标题） 马里奥播客
{date} YYYY-MM-DD 格式的发布日期 2024-03-15
{year} 发布年份 2024
{month} 发布月份（2 位数） 03
{day} 发布日期（2 位数） 15

注意： 如果模板中的花括号内容与上述任何令牌都不匹配（例如 {episode}），该文本将在生成的文件名中保持不变。

8.4 推荐模板

默认模板： {title} 默认模板仅使用节目标题。适用于标题具有描述性的目录。

通用用途（推荐）： {date} - {title} 结果：2024-03-15 - 第 187 集：人工智能通俗解读.mp3

推荐使用此格式，因为文件的字母排序与时间顺序一致。

多播客存档（共享文件夹）： {podcast} - {date} - {title} 结果：马里奥播客 - 2024-03-15 - 第 187 集.mp3

当所有播客保存在同一目标文件夹时很有用。

按年月组织到子文件夹： {year}/{month}/{date} - {title} 自动创建子文件夹结构（参见第 8.7 节）。

8.5 文件名自动规范化

某些字符在主要操作系统上不允许用于文件名：Windows 上禁止使用 /、\、:、*、?、"、<、>、|。

FeedDownloader Pro 会自动对模板生成的名称进行规范化：

  • 不允许的字符将替换为连字符（-）或被删除。
  • 连续空格缩减为单个空格。
  • 开头和结尾的连字符或空格被删除。
  • 如果名称超过文件系统限制，将截断至 240 个字符。

关于长标题的说明： 某些播客使用非常详细的标题（超过 150 个字符）。在模板中使用 {title} 令牌可能生成非常长的文件名。在这种情况下，将 {date} 作为主要时间元素可以限制名称的总长度。

8.6 配置模板

重命名模板在设置 → 元数据中配置。

文本字段接受任意文本和令牌的组合。字段下方提供实时预览，显示模板应用于示例节目的结果，以便在保存前验证格式。

默认模板为 {title}。

8.7 组织到子文件夹

在模板中可以使用 / 字符，在目标文件夹内自动创建子文件夹结构。

示例——按年月组织： {year}/{month}/{date} - {title}

目标文件夹为 D:\播客存档\马里奥播客\ 时，结果如下： D:\播客存档\马里奥播客\ ├── 2024\ │ ├── 01\ │ │ ├── 2024-01-08 - 年度第一集.mp3 │ │ └── 2024-01-22 - 第二集.mp3 │ └── 03\ │ └── 2024-03-15 - 第 187 集.mp3 └── 2023\ └── 12\ └── 2023-12-20 - 2023年最后一集.mp3

子文件夹不存在时会自动创建。

注意： 模板中不支持使用 \（反斜杠）作为路径分隔符。始终使用 /（正斜杠），软件会根据当前操作系统正确转换。

8.8 旁置 .json 文件

在设置 → 元数据选项卡中提供"旁置 .json 文件"开关。

启用后，每个已下载音频文件旁边会在同一文件夹中创建一个同名 .json 文件。该文件以结构化格式包含节目元数据：

{
  "title": "第 187 集：人工智能通俗解读",
  "podcast": "马里奥播客",
  "date": "2024-03-15",
  "sourceUrl": "https://media.example.com/ep187.mp3"
}

使用场景：

  • 与自动化脚本或直接从文件系统读取元数据（无需查询数据库）的系统集成。
  • 以独立于数据库的方式保存元数据，在存档迁移或重建时很有用。

此选项默认禁用。

8.9 ID3 标签

在设置 → 元数据选项卡中提供"ID3 标签"开关。

启用后，每次下载完成时，软件会将元数据直接写入 .mp3 文件的标准 ID3 标签中：

  • 标题： 节目标题
  • 艺术家： 播客名称
  • 年份： 发布年份
  • 封面： 播客图片（若 RSS feed 中有提供）

ID3 标签可被主要音频播放器（Windows Media Player、VLC、iTunes、Foobar2000）识别，无论文件名如何，均可显示节目信息。

注意： ID3 标签仅适用于 .mp3 文件。其他格式的文件（.m4a、.ogg、.opus）即使启用此选项也不会被修改。

此选项默认禁用。
