第 5 章：Feed 管理

5.1 什么是 RSS Feed

RSS feed 是播客发布的一个 XML 文档，让应用程序能够自动读取可用节目列表。当发布者发布新节目时，会更新此文档，添加新条目。播客应用程序会定期读取这些文档，以识别最新内容。

对于 FeedDownloader Pro，RSS feed 是主要数据来源：它包含节目列表、音频文件 URL、元数据（标题、日期、时长、描述、封面图片）以及播客的一般信息（名称、作者、分类）。

使用软件不需要了解 RSS feed 的内部结构，但有助于解读节目列表中显示的数据，以及理解某些信息缺失或不完整的原因。

5.2 有效 Feed 与问题 Feed

并非所有 RSS feed 都遵循相同的标准合规级别。

格式良好的 feed： 遵循 RSS 2.0 或 Atom 标准，包含所有必填字段（标题、链接、发布日期、带 MIME 类型的音频 URL），以及可选的 iTunes/Podcast Index 标签（时长、封面、季节信息）。FeedDownloader Pro 可无障碍读取这些 feed。

部分不完整的 feed： 缺少某些可选字段（时长、文件大小、节目封面）。软件仍会下载音频文件，但列表中某些列将为空。

音频 URL 不可访问的 feed： feed 可读，但音频文件 URL 指向已不存在的资源（404 错误）。这种情况在已停播或迁移至其他服务器的播客中很常见。FeedDownloader Pro 会在尝试下载后将这些节目标记为"错误"状态。

需要身份验证的 feed： 某些私人或付费播客需要 HTTP Basic 凭据才能访问 feed。软件支持这些 feed：凭据直接包含在 URL 中，格式为 https://用户名:密码@www.example.com/feed.xml。

5.3 分析 Feed：详细说明

点击"分析"时，FeedDownloader Pro 按顺序执行以下操作：

  1. URL 验证： 检查 URL 在语法上是否正确，并通过 5 项反 SSRF 检查（详见第 10 章）。
  2. HTTP 请求： 使用标准 user-agent 联系 feed 服务器。此操作的超时时间为 30 秒。
  3. XML 解析： 读取并分析 RSS 或 Atom 文档。软件能处理与标准略有偏差的 feed（未声明的编码、缺失标签、非常规命名空间）。
  4. 去重： 对 feed 中的每个节目，查询数据库以检查是否已经下载。音频 URL 用作唯一标识键。
  5. 填充列表： 所有节目连同当前状态一起显示。
  6. 添加到订阅源库： 如果订阅源尚未存在，将被永久添加到侧边栏。已存在于订阅源库中的订阅源会以最新的节目数量进行更新。

5.4 订阅源库

FeedDownloader Pro 维护一份永久订阅源库。每个已分析的订阅源都会保存在侧边栏中，并在会话之间保持可用，无需在每次启动时重新输入 URL。

显示内容

订阅源库中的每个条目显示：播客封面（缩略图）、标题、与服务器最近一次同步的日期，以及一个数字徽章，指示自上次下载以来已发布的节目数量。下载完所有新节目后，徽章会消失。

点击侧边栏中的订阅源会立即在主区域更新节目列表。

从订阅源库中移除订阅源

要移除订阅源，将鼠标悬停在侧边栏中的条目上：右侧会出现垃圾桶按钮。点击它会打开确认对话框。移除操作会从订阅源库中删除该订阅源，但不会删除已下载的音频文件，也不会删除数据库中的相关数据；节目仍可在归档视图中看到。

搜索和排序

  • 订阅源搜索： 侧边栏顶部的搜索字段按名称实时筛选订阅源。对大型订阅源库很有用。
  • A–Z 排序： 排序按钮按标题字母顺序排列订阅源。再次点击恢复原始顺序。

隐私说明： 订阅源库仅保存在本地数据库中。不会向外部服务器传输任何数据。

5.5 从 OPML 导入 Feed

OPML（Outline Processor Markup Language）是在不同应用程序之间导出和导入播客列表的标准格式。如果你在 Pocket Casts、Overcast、AntennaPod 或任何其他客户端中有播客库，可以将其导出为 OPML 并直接导入 FeedDownloader Pro。

如何导入 OPML 文件：

  1. 前往设置 → 存档，找到"数据与可移植性"部分。
  2. 点击导入订阅源 (OPML)，并选择从播客应用导出的 .opml 文件。
  3. FeedDownloader Pro 解析该文件并将识别到的订阅源添加到订阅源库。

注意： 某些播客应用使用专有的 OPML 格式变体。FeedDownloader Pro 支持最常见的版本。如果文件无法正确导入，请用文本编辑器打开，检查每个播客是否存在 <outline type="rss" xmlUrl="..."> 标签。

5.6 将库导出为 OPML

可以将订阅源库以 OPML 格式导出，用于：

  • 创建播客列表的备份。
  • 与其他用户或软件的另一个安装实例共享。
  • 导入到播客应用中以订阅相同的订阅源。

如何导出：

  1. 前往设置 → 存档，找到"数据与可移植性"部分。
  2. 点击导出订阅源 (OPML)，为文件选择名称和保存位置。
  3. 生成的文件与任何支持 OPML 标准的应用程序兼容。

5.7 大型 Feed

某些历史播客或广播制作存档可能拥有数千个节目，RSS 文件体积相当大。在这种情况下：

  • 初始分析需要更长时间： 拥有 2,000 个节目的 feed 可能需要 15–30 秒才能完成下载和解析。这是预期行为。
  • 列表虚拟化： 拥有数千个条目时，列表只加载屏幕上可见的行，以保持界面响应流畅。
  • 估算所需空间： 2,000 个节目，每个约 50 MB，总量约为 100 GB。请在继续操作前确认有足够的可用空间。

5.8 管理多个订阅源

FeedDownloader Pro 原生支持管理多个订阅源的订阅源库。可添加的播客数量没有限制：全部保存在侧边栏中，并在会话之间保持可访问。

在订阅源之间导航

点击侧边栏中的订阅源会立即在主区域更新节目列表。软件会记住上次关闭时所选的订阅源。

同步订阅源

  • 单独同步： 将鼠标悬停在侧边栏中的订阅源条目上以显示同步图标。点击它会让软件从服务器重新读取该订阅源，并用任何新节目更新列表。
  • 全部同步： "全部同步"按钮可在单次操作中并行刷新所有订阅源。在此过程中，侧边栏中的每个缩略图实时显示自身状态。完成后，任何新节目都会通过新节目徽章突出显示。

有关无需手动干预的计划自动更新，请参见第 5.9 节。

5.9 订阅源自动更新

FeedDownloader Pro 可以在后台按固定间隔自动同步所有订阅源，无需用户进行任何操作。

配置

设置位于设置 → 通用 → 订阅源自动更新。有四种可用选项：

选项 行为
禁用（默认） 不进行自动同步。
每 6 小时 软件自启动起每 6 小时同步所有订阅源。
每 12 小时 软件自启动起每 12 小时同步所有订阅源。
每 24 小时 软件自启动起每 24 小时同步一次所有订阅源。

设置更改立即生效，无需重启软件。计时器从应用程序启动开始计时。

行为

自动更新不会启动下载：它仅检查是否发布了新节目。如果在自动同步期间在一个或多个订阅源上发现新节目，系统会发送操作系统通知，包含所发现内容的摘要（在所有 8 种支持的语言中均可用）。

要下载提示的新节目，请打开软件并使用常规的批量控件。

参见第 6 章，了解下载引擎的详细说明。
