第 9 章：完整性、统计与归档

9.1 为何需要验证文件完整性

下载完成并不能保证收到的文件是完好的。传输过程中丢失的网络数据包、磁盘写入错误或最后一秒的中断，都可能产生形式上"存在"但实际已损坏的文件。在没有明确验证的情况下，表面上完整的存档可能包含无法播放的音频文件，其损坏只有在播放时才会被发现。

FeedDownloader Pro 通过两种互补机制应对这一问题：大小验证（下载过程中）和 SHA-256 验证（完成时）。

9.2 SHA-256 验证

SHA-256（安全哈希算法 256 位）是一种加密函数，为任何文件生成 64 个十六进制字符的数字指纹。两个相同的文件始终产生相同的哈希值；即使只有一位之差，也会产生完全不同的哈希值。

对于每个已下载的文件，FeedDownloader Pro 会：

  1. 在下载结束时计算文件的 SHA-256 哈希值。
  2. 将哈希值连同文件路径和计算日期一起保存在数据库中。
  3. 如果 RSS feed 包含参考哈希值（某些现代 feed 包含 <podcast:integrity> 字段），则将其与计算出的哈希值进行比对。如有不符，文件将被标记为"已损坏"并重新加入队列进行重新下载。

实际用途：

  • 可以在未来任意时刻验证文件是否未被修改、损坏或替换：只需重新计算哈希值并与数据库中记录的值进行比对。
  • 将文件迁移到新磁盘后，存档检查（参见第 9.4 节）可验证所有文件是否仍然存在。
  • 在专业场景中，SHA-256 哈希值是下载时内容完整性的可验证参考。

9.3 提取的音频元数据

每次下载完成后，FeedDownloader Pro 会自动提取音频文件的技术元数据。这些信息直接从文件读取（而非从 RSS feed 读取），并记录在数据库中。

提取的元数据：

字段 说明 示例
比特率 以千比特每秒为单位的音频质量 128 kbps、320 kbps
采样率 采样频率 44100 Hz、48000 Hz
磁盘大小 已下载文件的实际大小 67.4 MB

这些值记录在数据库中，并包含在 CSV 导出中（参见第 9.6 节）。

9.4 存档检查：验证存档完整性

随着时间推移，存档可能会发生软件外部的更改：直接在文件系统中移动或删除的文件。存档检查会根据数据库中的记录验证存档状态。

如何执行存档检查： 前往设置 → 存档 → 存档检查，点击"开始检查"。

该过程分析数据库中记录的每个文件，验证其是否仍存在于记录的路径中。完成后，显示包含三个指标的摘要：

指标 含义
总计 数据库中的节目总数
存在 存在于记录路径中的文件
缺失 在记录路径中未找到的文件

屏幕还显示现有文件占用的磁盘总空间。

如果存在缺失文件，软件会列出前 5 个，包含播客名称和文件名。要恢复缺失文件，请使用主列表中节目右键菜单中的"强制重新下载"功能。

9.5 存档统计

统计部分可从设置 → 存档访问，提供数据库中记录数据的简明概览：

  • 已下载文件： 数据库中的节目总数。
  • 播客： 存档中所涵盖的不同 feed 数量。
  • 时间范围： 已下载的第一个和最后一个节目的日期。

每次打开设置面板时，统计数据会自动更新。

9.6 CSV 导出

CSV 导出会生成一个包含数据库中每个节目数据的文件。它对于将 FeedDownloader Pro 与其他工具（电子表格、内容管理系统、自动化脚本）集成非常有用。

如何导出： 前往设置 → 存档 → 导出 CSV，选择保存文件的路径。

导出列：

列 内容
Podcast 播客名称
Episode Title 节目标题
Publish Date 发布日期
Downloaded At 下载日期和时间
File Size (bytes) 文件大小（字节）
Bitrate (kbps) 以千比特每秒为单位的音频比特率
Sample Rate (Hz) 以赫兹为单位的采样率
SHA-256 Checksum 文件的 SHA-256 哈希值
Validation Status 最近一次完整性检查结果
GUID RSS feed 中节目的唯一标识符

文件格式： 逗号（,）分隔的 CSV，带 BOM 的 UTF-8 编码（与 Microsoft Excel 兼容）。包含逗号的字段用引号括起来。

9.7 存档迁移

要将存档移至新磁盘或新文件夹，请使用内置迁移功能，该功能会保持数据库与文件新位置的同步。

操作步骤：

  1. 前往设置 → 存档 → 迁移存档。
  2. 通过选择窗口选择新目标文件夹。
  3. 软件将所有音频文件物理移动到新文件夹，并更新数据库中的路径。
  4. 完成后显示摘要：已移动文件数量及任何错误信息。

注意： 迁移操作将文件从当前文件夹移动到新文件夹。文件将从原始位置删除。开始操作前，请确认目标磁盘有足够的可用空间。

迁移至新计算机： 同时复制音频文件文件夹和 feeddownloader.db 文件（位于第 2 章所述的用户数据文件夹中）。在新计算机上安装 FeedDownloader Pro，将数据库复制到用户数据文件夹，如果存档路径发生变化，请使用迁移功能。

参见第 10 章，了解软件的高级设置。
