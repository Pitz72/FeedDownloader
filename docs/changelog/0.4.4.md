# 🔒 v0.4.4 — "URL Guard"

> Data rilascio: 20 marzo 2026

Questa release risolve una **criticità gravissima di sicurezza**: l'assenza totale di validazione degli URL nel main process Electron, che esponeva l'applicazione a potenziali attacchi SSRF (Server-Side Request Forgery).

---

## 🔴 Fix Criticità Gravissima: Nessuna Validazione URL

### Il Problema

Gli handler IPC `PARSE_FEED` e `START_DOWNLOAD` passavano l'URL ricevuto dal renderer **direttamente ad Axios** senza alcun controllo:

```typescript
// ❌ PRIMA (v0.4.0–v0.4.3)
ipcMain.handle('parse-feed', async (_, url: string) => {
    return await feedService.parseFeed(url); // URL non validato!
});
```

Questo significava che un URL arbitrario poteva:
- **`file:///etc/passwd`** → accedere a file locali del filesystem
- **`http://127.0.0.1:3000/admin`** → raggiungere servizi locali (database, API interne)
- **`http://192.168.1.1/config`** → accedere al router/NAS sulla rete locale
- **`http://169.254.169.254/`** → leggere metadati AWS/GCP/Azure (cloud SSRF)
- **`ftp://`, `gopher://`** → protocolli pericolosi con potenziale di exploit
- **`javascript:`, `data:`** → tentativi di injection

### La Soluzione: `validateUrl()` con Difesa Multi-Livello

Creata la utility `validateUrl()` in `electron/utils/validateUrl.ts` che implementa 5 livelli di validazione:

#### Livello 1 — Input vuoto/invalido
```
'' → URL_EMPTY
'not a url' → URL_INVALID
'example.com/feed' → URL_INVALID (manca il protocollo)
```

#### Livello 2 — Whitelist protocolli
Solo `http://` e `https://` sono permessi. Tutto il resto è bloccato:
```
file:///etc/passwd → URL_PROTOCOL_BLOCKED
ftp://ftp.evil.com → URL_PROTOCOL_BLOCKED
javascript:alert(1) → URL_PROTOCOL_BLOCKED
data:text/html,... → URL_PROTOCOL_BLOCKED
gopher://evil.com/ → URL_PROTOCOL_BLOCKED
```

#### Livello 3 — Blocco hostname interni
```
http://localhost/feed → URL_PRIVATE_HOST
http://localhost:3000/ → URL_PRIVATE_HOST
http://localhost.localdomain/ → URL_PRIVATE_HOST
http://0.0.0.0/ → URL_PRIVATE_IP
```

#### Livello 4 — Blocco IP privati (RFC 1918 + RFC 3927)
| Range | Blocco | Uso tipico |
|-------|--------|------------|
| `127.0.0.0/8` | ✅ | Loopback |
| `10.0.0.0/8` | ✅ | Rete privata classe A |
| `172.16.0.0/12` | ✅ | Rete privata classe B |
| `192.168.0.0/16` | ✅ | Rete privata classe C |
| `169.254.0.0/16` | ✅ | Link-local / Cloud metadata |
| `0.0.0.0/8` | ✅ | Indirizzo non specificato |

> **Nota sicurezza cloud:** `169.254.169.254` è l'endpoint dei metadati su AWS EC2, GCP e Azure. È il vettore SSRF più sfruttato in ambienti cloud.

#### Livello 5 — Blocco IPv6 privati
```
http://[::1]/feed → URL_PRIVATE_HOST (loopback)
http://[fc00::1]/ → URL_PRIVATE_IP (unique-local)
http://[fd12::1]/ → URL_PRIVATE_IP (unique-local)
http://[fe80::1]/ → URL_PRIVATE_IP (link-local)
```

### Dove viene applicata la validazione

```diff
 // PARSE_FEED — prima di fare qualsiasi richiesta HTTP
 ipcMain.handle('parse-feed', async (_, url: string) => {
+    const check = validateUrl(url);
+    if (!check.valid) throw new Error(check.error);
     return await feedService.parseFeed(url);
 });

 // START_DOWNLOAD — prima di scaricare qualsiasi file
 ipcMain.handle('start-download', async (_, { url, ... }) => {
+    const check = validateUrl(url);
+    if (!check.valid) throw new Error(check.error);
     // ...download logic
 });
```

## ⚠️ Note per il Frontend

Quando `validateUrl` rifiuta un URL, l'handler IPC lancia un `Error` con uno dei seguenti codici:

| Codice errore | Significato | Azione consigliata nel frontend |
|---------------|-------------|-------------------------------|
| `URL_EMPTY` | L'URL è vuoto | Mostrare "Inserisci un URL" |
| `URL_INVALID` | L'URL non è parsabile | Mostrare "URL non valido" |
| `URL_PROTOCOL_BLOCKED` | Protocollo non HTTP/HTTPS | Mostrare "Usa un URL http:// o https://" |
| `URL_PRIVATE_HOST` | Hostname interno (localhost) | Mostrare "URL non raggiungibile" |
| `URL_PRIVATE_IP` | IP di rete privata | Mostrare "URL non raggiungibile" |
| `URL_NO_HOST` | URL senza hostname | Mostrare "URL non valido" |

Il componente `UrlInput.tsx` può catturare questi errori per mostrare messaggi localizzati con i18next.
