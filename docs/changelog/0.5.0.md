## ✨ Feature 1: Drag & Drop URL (`src/components/UrlInput.tsx`)

### Il Problema
L'unico modo per aggiungere un feed era copiare manualmente l'URL e incollarlo nel campo di input.

### La Soluzione

Il componente `UrlInput` ora accetta URL RSS trascinati direttamente sull'area di input da qualsiasi sorgente (browser, file manager, editor di testo):

```tsx
// Feedback visivo durante il trascinamento
<div
    className={`... ${isDragging ? 'ring-2 ring-blue-500/60 bg-blue-500/5' : ''}`}
    onDragOver={handleDragOver}
    onDragLeave={handleDragLeave}
    onDrop={handleDrop}
>
```

**Comportamento:**
- Il bordo del campo si illumina di blu al passaggio del cursore trascinato
- Il placeholder cambia in `t('input.drop_url')` durante il drag
- Al rilascio, l'URL viene estratto da `text/plain` o `text/uri-list`, inserito nel campo e analizzato automaticamente
- Tutta la logica di analisi è stata estratta in `analyzeFeed(url)` — funzione condivisa tra click, Enter e drop, eliminando la duplicazione

**Nuova chiave i18n:** `input.drop_url` (8 lingue)

## ✨ Feature 2: Scorciatoie tastiera

### 2a — Esc chiude i modali (`src/components/ConfirmModal.tsx`)

```typescript
useEffect(() => {
    if (!isOpen) return;
    const handleKeyDown = (e: KeyboardEvent) => { if (e.key === 'Escape') onCancel(); };
    window.addEventListener('keydown', handleKeyDown);
    return () => window.removeEventListener('keydown', handleKeyDown);

```

Ogni modale di conferma (download di massa, rimozione feed, reset stato) ora si chiude con `Esc` senza cliccare il pulsante Annulla.

### 2b — Ctrl+F focalizza il filtro episodi (`src/App.tsx` + `src/components/EpisodeList.tsx`)


## ✨ Feature 3: Tray icon — Minimizza nella barra di sistema (`electron/main.ts`)

### Il Problema
Chiudere la finestra terminava l'applicazione. Non era possibile tenere il programma attivo in background.

### La Soluzione

L'app ora si minimizza nella **system tray** (barra delle applicazioni / area di notifica) invece di chiudersi. Funziona su **Windows e Linux** (su macOS è gestito nativamente dal dock).

```typescript
// Crea l'icona nella tray con menu contestuale
function createTray() {
    tray = new Tray(icon);
    tray.setToolTip('Runtime FeedDownloader Pro');
    tray.setContextMenu(Menu.buildFromTemplate([
        { label: 'Show', click: () => { win?.show(); win?.focus(); } },
        { type: 'separator' },
        { label: 'Quit', click: () => { isQuiting = true; app.quit(); } },
    ]));
    // Click sinistro: toggle visibilità finestra
    tray.on('click', () => {
        if (win?.isVisible()) { win.hide(); } else { win?.show(); win?.focus(); }
    });
}

// Intercetta il close: nasconde invece di chiudere
win.on('close', (event) => {
    if (!isQuiting) { event.preventDefault(); win?.hide(); }
});

// Flag per distinguere quit vero (menu tray) da close (X della finestra)
let isQuiting = false;
app.on('before-quit', () => { isQuiting = true; });
```

**Comportamento:**
- **X sulla finestra** → finestra nascosta, app attiva in background
- **Click sull'icona tray** → toggle visibilità (show/hide)
- **Tasto destro → Show** → porta in primo piano
- **Tasto destro → Quit** → chiude definitivamente
- **Spegnimento OS** → `before-quit` imposta `isQuiting = true`, la finestra si chiude normalmente

## ✨ Feature 4: Verifica integrità file (`electron/services/DownloadService.ts`)

### Il Problema
Un download poteva completarsi con un file parziale (es. connessione caduta durante lo streaming) senza che l'errore venisse rilevato, poiché il `writer.on('finish')` scattava comunque.

### La Soluzione

Dopo il completamento della scrittura, prima del rename atomico `.part → file finale`, viene confrontata la dimensione effettiva con il `Content-Length` dichiarato dal server:

```typescript
writer.on('finish', async () => {
    if (stallTimer) clearTimeout(stallTimer);

    // Integrity check: verify downloaded size matches Content-Length
    if (totalLength) {
        const expected = parseInt(totalLength);
        if (expected > 0 && Math.abs(loaded - expected) / expected > 0.01) {
            await fs.remove(tempPath).catch(() => { });
            reject(new Error('INTEGRITY_CHECK_FAILED'));
            return;
        }
    }

    await fs.rename(tempPath, outputPath);
    resolve();
});
```

- Tolleranza: **1%** — gestisce piccole discrepanze dovute a encoding o compressione
- Se la verifica fallisce, il file parziale viene eliminato e il download entra nel ciclo di **retry con backoff esponenziale** (1s, 2s, 4s)
- Se il server non invia `Content-Length`, la verifica viene saltata (comportamento invariato)

## ✨ Feature 5: Rilevamento episodi "ghost" 404 (`electron/services/DownloadService.ts` + `electron/ipc.ts` + `src/App.tsx`)

### Il Problema
Gli episodi rimossi dai server CDN ma ancora presenti nei feed RSS causavano errori generici silenziosi. L'utente non sapeva se il file fosse effettivamente scomparso o se si trattasse di un problema temporaneo di rete.

### La Soluzione — 3 livelli

**Livello 1 — DownloadService: rileva il 404**
```typescript
const response = await axios({ url, method: 'GET', responseType: 'stream', timeout: CONNECTION_TIMEOUT_MS });

// Ghost episode detection
if (response.status === 404) {
    writer.close();
    await fs.remove(tempPath).catch(() => { });
    throw new Error('EPISODE_NOT_FOUND');
}
```

**Livello 2 — DownloadService: non ritenta (errore permanente)**
```typescript
if (err.message === 'EPISODE_NOT_FOUND') throw error; // 404 is permanent, no retry
```

**Livello 3 — ipc.ts: propaga il flag al Renderer**
```typescript
const isNotFound = (error as Error).message === 'EPISODE_NOT_FOUND';
pushEvent(mainWindow, CH.DOWNLOAD_PROGRESS, {
    url, loaded: 0, total: 0, error: true,
    ...(isNotFound ? { notFound: true } : {})
});
```

**Livello 4 — App.tsx: toast specifico per ghost episodes**
```typescript
if (data.error) {
    if (data.notFound) {
        toast.show(t('toast.episode_not_found'), 'error'); // "Episodio non disponibile (404)"
    } else {
        toast.show(t('toast.download_error'), 'error');    // "Download fallito."
    }
}
```

**Tipo aggiornato** in `shared/types.ts`:
```typescript
export interface DownloadProgress {
    url: string;
    loaded: number;
    total: number;
    completed?: boolean;
    error?: boolean;
    notFound?: boolean; // v0.5.0 — ghost episode: server returned 404
}
```

**Nuove chiavi i18n:** `toast.episode_not_found`, `toast.download_error` (8 lingue)

### 3. Bug critico: Ghost Process — finestra mai visibile al lancio dell'eseguibile

**Sintomo:** Dopo l'installazione e il lancio dell'app, nessuna finestra appariva. Il processo era visibile nel Task Manager ma nessuna UI veniva mai mostrata. L'unica soluzione era terminare il processo manualmente.

#### Diagnosi — Round 1: Tray icon

Ipotesi iniziale: il crash era causato dalla tray icon (PNG dentro l'asar). Aggiunti try-catch in `createTray()`, handler `did-fail-load`, e controllo `if (!tray) app.quit()` in `window-all-closed`. **Problema persisteva.**

#### Diagnosi — Round 2: Logger su file

Aggiunto logger su file (`%TEMP%/fdpro-startup.log`) all'avvio del processo main. Il file **non veniva mai creato**, confermando che il crash avveniva durante la **risoluzione degli import ES module** — prima ancora che la prima riga di codice non-import potesse eseguire.

#### Causa radice — livello 1: `better_sqlite3.node` dentro l'asar

I file `.node` (moduli nativi compilati) non possono essere caricati dall'interno di un archivio `.asar`. Ispezione dell'asar:

```
node -e "require('asar').listPackage('app.asar')"
```

Il file `better_sqlite3.node` era dentro l'asar e **non** nella directory `app.asar.unpacked/`.

**Fix parziale applicato:** aggiunto `asarUnpack` in `package.json`:

```json
"asarUnpack": ["**/*.node"]
```

Il file veniva estratto correttamente in `app.asar.unpacked/`, ma il crash **persisteva**.

#### Causa radice — livello 2 (vera causa): Vite bundla `better-sqlite3` inline in `main.js`

```bash
grep "better-sqlite3" dist-electron/main.js
# Output: 22.000+ righe di codice della libreria bundlato inline
```

`vite-plugin-electron/simple` compilava `better-sqlite3` direttamente dentro `dist-electron/main.js`. Il resolver interno alla build (`pY()("better_sqlite3.node")`) non gestisce i path asar in modo corretto, rendendo `asarUnpack` da solo insufficiente.

#### Soluzione finale — due modifiche combinate

**`vite.config.ts`** — impedisce a Vite di bundlare il modulo nativo:

```typescript
main: {
  entry: 'electron/main.ts',
  vite: {
    build: {
      rollupOptions: {
        // Native modules must NOT be bundled — they load .node files at runtime
        external: ['better-sqlite3'],
      },
    },
  },
},
```

**`package.json`** — estrae il `.node` dall'asar (richiesto comunque):

```json
"asarUnpack": ["**/*.node"],
"files": ["dist", "dist-electron", "node_modules", "package.json"]
```

Dopo entrambe le modifiche: `dist-electron/main.js` contiene `import Zu from "better-sqlite3"` (import esterno, non inline). L'app si avvia correttamente.

> **Regola appresa:** `asarUnpack` da solo non è sufficiente se Vite bundla il modulo nativo. Servono **entrambe** le fix: `external` in vite config + `asarUnpack` in electron-builder config.

### 4. Perdita dati utente al primo avvio post-upgrade

**Sintomo:** tutti i feed e gli episodi precedentemente salvati sono scomparsi dopo l'aggiornamento a v0.5.0.

**Causa:** v0.5.0 introduce `better-sqlite3` (SQLite) come storage principale, sostituendo `electron-store` (JSON). Non è stata implementata alcuna migrazione automatica dal vecchio formato JSON al nuovo database SQLite.

**Stato:** accettato come known issue per questa release. Una migrazione `electron-store → SQLite` potrà essere considerata in una release futura se necessario.
