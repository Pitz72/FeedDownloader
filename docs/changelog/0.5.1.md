# v0.5.1 — Security Hardening & Cleanup

> Rilasciato il 26 marzo 2026
> Versione precedente: [v0.5.0](0.5.0.md)

Questa release applica un intervento di **bonifica tecnica** su criticità gravi e lievi identificate durante l'analisi approfondita del codice post-v0.5.0. Nessuna nuova funzionalità: focus esclusivo su sicurezza, correttezza e pulizia del progetto.

## 🟠 Fix Criticità Gravi

### G1 — `nodeIntegration: false` e `contextIsolation: true` espliciti

**File:** `electron/main.ts`

**Problema:** La configurazione `webPreferences` di `BrowserWindow` specificava solo `preload`, lasciando impliciti i valori di sicurezza critici `nodeIntegration` e `contextIsolation`. In Electron 30 i default sono corretti (`nodeIntegration: false`, `contextIsolation: true`), ma affidarsi ai default è una pratica rischiosa: una futura modifica alla configurazione o un aggiornamento di Electron potrebbe alterarli silenziosamente senza evidenza nel codice.

**Fix:** Rese esplicite le proprietà di sicurezza nel blocco `webPreferences`:

```typescript
// Prima (v0.5.0)
webPreferences: {
  preload: path.join(__dirname, 'preload.mjs'),
}

// Dopo (v0.5.1)
webPreferences: {
  preload: path.join(__dirname, 'preload.mjs'),
  nodeIntegration: false,
  contextIsolation: true,
  sandbox: false, // sandbox:true incompatibile con preload + better-sqlite3 native module
}
```

**Nota su `sandbox`:** `sandbox: true` è la configurazione più restrittiva possibile ma è incompatibile con i moduli nativi Node.js caricati nel preload (come `better-sqlite3`). Il valore `false` è corretto e intenzionale per questa architettura.

### G2 — Rate limiting su `PARSE_FEED`

**File:** `electron/ipc.ts`

**Problema:** L'handler IPC `PARSE_FEED` non aveva alcuna protezione contro invocazioni ripetute in rapida successione. Un bug nella UI o un input utente anomalo (es. pressione rapida del tasto Invio, drag & drop multiplo) potrebbe scatenare decine di richieste HTTP simultanee verso server RSS esterni, potenzialmente causando ban IP da parte dei CDN o saturazione del thread principale di Electron.

**Fix:** Aggiunto un meccanismo di cooldown per URL: ogni URL può essere analizzato al massimo una volta ogni 3 secondi. Richieste entro la finestra di cooldown vengono rifiutate con errore `RATE_LIMITED`.

```typescript
// Struttura dati: Map URL → timestamp ultima chiamata
const parseFeedLastCall = new Map<string, number>();
const PARSE_FEED_COOLDOWN_MS = 3000;

// Logica nell'handler
const now = Date.now();
const lastCall = parseFeedLastCall.get(url);
if (lastCall !== undefined && (now - lastCall) < PARSE_FEED_COOLDOWN_MS) {
    throw new Error('RATE_LIMITED');
}
parseFeedLastCall.set(url, now);
```

**Impatto:** Nessun impatto sull'uso normale. Un utente che analizza feed in rapida successione su URL differenti non è toccato. Solo richieste duplicate sullo stesso URL vengono bloccate.

## 🟡 Fix Criticità Medie

### M1 — Rimozione di `electron-store` da `package.json`

**File:** `package.json`

**Problema:** `electron-store` (v11.0.2) era ancora presente nelle `dependencies` nonostante la migrazione completa a SQLite avvenuta in v0.4.6. La dipendenza veniva installata, compilata e inclusa nel bundle dell'applicazione senza essere importata da nessun modulo. Questo comportava:
- Aumento del peso del bundle (~150KB inutili)
- Dipendenza aggiuntiva da aggiornare per patch di sicurezza
- Potenziale confusione per sviluppatori futuri

**Fix:** Rimossa la voce `"electron-store": "^11.0.2"` da `dependencies`.

> **Nota:** I dati storici degli utenti che avevano usato versioni precedenti a v0.4.6 (salvati in `electron-store`) non sono migrabili automaticamente. Questo è un known issue accettato documentato nel changelog v0.4.6.

## 🔵 Fix Criticità Lievi

### L1 — Aggiunto `engines` field in `package.json`

**File:** `package.json`

**Problema:** Nessuna indicazione della versione Node.js richiesta. Utenti con Node 16 (EOL) o configurazioni non standard potrebbero riscontrare incompatibilità con `better-sqlite3` (modulo nativo che richiede Node ≥18) senza un messaggio di errore chiaro.

**Fix:**

```json
"engines": {
  "node": ">=18.0.0"
}
```

---

### L2 — Rimozione file boilerplate Vite mai usati

**Problema:** Il progetto conteneva 4 file SVG residui dal template di scaffolding `electron-vite` che non venivano referenziati da nessun componente, stile o configurazione:

| File | Tipo |
|------|------|
| `public/vite.svg` | Logo Vite (template) |
| `public/electron-vite.svg` | Logo electron-vite (template) |
| `public/electron-vite.animate.svg` | Logo animato electron-vite (template) |
| `src/assets/react.svg` | Logo React (template) |

**Fix:** File eliminati. `public/noise.svg` è stato mantenuto — è attivamente usato come texture di sfondo in `App.tsx` e `IntroScreen.tsx`.
