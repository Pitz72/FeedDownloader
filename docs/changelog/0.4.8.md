# 🧹 v0.4.8 — "Code Hygiene"

> Data rilascio: 20 marzo 2026

Questa release risolve le **prime tre criticità medie** del report v0.4.0, migliorando la manutenibilità del codice e la robustezza dell'export dati.

---

## 🟡 Fix 1: Duplicazione Logica Enclosure URL

### Il Problema
In `EpisodeList.tsx` la logica per estrarre l'URL audio da un episodio era **ripetuta 3 volte**:

```typescript
// ❌ Duplicato x3
let url = episode.enclosure?.url;
if (!url && episode.enclosures && episode.enclosures.length > 0) {
    url = episode.enclosures[0].url;
}
```

### La Soluzione
Creata una funzione di utilità centralizzata `getEnclosureUrl()` in `shared/getEnclosureUrl.ts`:

```typescript
export function getEnclosureUrl(episode: Episode): string | undefined {
    return episode.enclosure?.url
        || (episode.enclosures && episode.enclosures.length > 0
            ? episode.enclosures[0].url
            : undefined);
}
```

**Benefici:**
- Sostituite 3 occorrenze in `EpisodeList.tsx` con `getEnclosureUrl(episode)`.
- Ridotta la duplicazione del codice.
- Creata una suite di 6 test (`getEnclosureUrl.test.ts`) per coprire tutti gli edge case (enclosure singolo, array, assente, vuoto).

## 🟡 Fix 2: Nessuna Gestione Errori nei Push Event Listeners

### Il Problema
I listener degli eventi IPC (push) dal Main process venivano assegnati direttamente ai callback React senza blocchi `try/catch`. 

Se il Main process inviava dati malformati o se il callback sollevava un'eccezione, il rendering Crashava portando all'arresto anomalo della vista (White Screen).

### La Soluzione
Aggiunti blocchi `try/catch` protettivi in:
- `Sidebar.tsx:36` (`onFeedsUpdated`)
- `EpisodeList.tsx:41` (`onDownloadsUpdated`)

```typescript
const removeListener = window.api.onFeedsUpdated((_event, updatedFeeds) => {
    try {
        setFeeds(updatedFeeds);
    } catch (err) {
        console.error('Error in onFeedsUpdated:', err);
    }
});
```

Questo garantisce che l'applicazione rimanga in piedi anche in caso di anomalie nei dati trasmessi.

## 🟡 Fix 3: CSV Export Vulnerabile a Injection

### Il Problema
In `DatabaseService.ts` il metodo `exportArchiveCSV()` era vulnerabile a due problemi:
1. **Spezzamento Strutturale**: Se un titolo contiene caratteri di a capo (`\n`), il file CSV si rompeva su più righe.
2. **Compatibilità Excel**: I caratteri accentati (UTF-8) venivano visualizzati corrotti se si apriva il file con Microsoft Excel senza importazione manuale.

### La Soluzione
1. **Escape Newlines**: Sostituiti i ritorni a capo con spazi prima del wrapping in virgolette doppie:
    ```typescript
    const escaped = s.replace(/"/g, '""').replace(/[\n\r]+/g, ' ');
    ```
2. **Compatibilità**: Aggiunto il **BOM** (Byte Order Mark) UTF-8 (`\uFEFF`) all'inizio del file per forzare Excel a interpretarlo correttamente:
   ```typescript
   let csv = '\uFEFFPodcast,Episode Title,Publish Date,Downloaded At,GUID\n';
   ```
