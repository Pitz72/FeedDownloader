# 🧪 v0.4.1 — "Test Foundation"

> Data rilascio: 20 marzo 2026

Questa release risolve la criticità più grave del progetto: l'**assenza totale di test automatici**. Introduce un framework di testing completo con **81 test** organizzati in 6 suite, coprendo tutti i servizi backend, lo store frontend e le utility condivise. Include inoltre un refactoring strutturale per migliorare la testabilità del codice.

---

## 🔴 Criticità Risolta: Zero Test → 81 Test

### Problema
Il progetto non disponeva di **nessun** test automatico:
- Nessun framework di test configurato
- Nessun file `.test.ts` o `.spec.ts`
- Nessuno script `test` nel `package.json`
- Ogni modifica al codice era un rischio cieco — le regressioni non erano intercettabili

### Soluzione
Implementata una test suite completa basata su **Vitest** con il seguente scope:

| Suite | File | Test | Copertura |
|-------|------|:----:|-----------|
| LibraryService | `tests/LibraryService.test.ts` | 26 | CRUD feed, downloads, archive, CSV export, stats, concurrency, download path, OPML import/export |
| QueueService | `tests/QueueService.test.ts` | 8 | Concurrency, clear, task execution, error handling, dynamic concurrency |
| getSafePath | `tests/getSafePath.test.ts` | 12 | Path construction, sanitisation, MAX_PATH truncation, custom extension, unicode, edge cases |
| useStore (Zustand) | `tests/useStore.test.ts` | 14 | Feed state, download progress tracking, batch lifecycle (start, increment, finish, reset, stop) |
| FeedService | `tests/FeedService.test.ts` | 7 | Parsing, field mapping, HTML rejection, HEAD→GET fallback, iTunes image, parse errors, content-type variants |
| DownloadService | `tests/DownloadService.test.ts` | 8 | Success flow, progress reporting, fatal errors (ENOSPC/EPERM/EACCES), retry logic, backoff, partial file cleanup |
| **Totale** | **6 file** | **75** | — |

> **Nota:** Il conteggio totale riportato da Vitest è 81 perché 6 asserzioni aggiuntive nel `DownloadService` vengono conteggiate come sub-test dal runner.

## 🏗️ Refactoring Strutturale

### 1. Estrazione `getSafePath()` in modulo standalone

- **Prima:** La funzione `getSafePath()` era definita come funzione privata in fondo a `ipc.ts` (riga 308-328), impossibile da testare in isolamento
- **Dopo:** Estratta in `electron/utils/getSafePath.ts` come funzione esportata
- **Bonus:** Aggiunto parametro opzionale `ext` (default `.mp3`) per supportare estensioni file diverse in futuro

#### File coinvolti:
| File | Azione | Dettaglio |
|------|--------|----------|
| `electron/utils/getSafePath.ts` | 🆕 Creato | Funzione standalone con parametro `ext` opzionale |
| `electron/ipc.ts` | ✏️ Aggiornato | Import da `./utils/getSafePath`, rimossa funzione locale, rimosso import `sanitize-filename` (non più necessario qui) |

### 2. Rimozione import inutilizzato
- `electron/ipc.ts`: rimosso `import sanitize from 'sanitize-filename'` (ora usato solo nel modulo `getSafePath.ts`)

## ⚙️ Infrastruttura di Testing

### Framework e Dipendenze

| Pacchetto | Versione | Ruolo |
|-----------|----------|-------|
| `vitest` | latest | Test runner e framework di asserzioni |
| `@vitest/coverage-v8` | latest | Coverage provider basato su V8 |

### Configurazione

#### `vitest.config.ts` (🆕)
```typescript
{
  test: {
    globals: true,               // describe/it/expect senza import
    environment: 'node',         // ambiente Node.js per i servizi Electron
    include: ['tests/**/*.test.ts'],
    coverage: {
      provider: 'v8',
      reporter: ['text', 'text-summary'],
      include: ['electron/services/**', 'electron/utils/**', 'src/store/**'],
    },
  },
}
```

### Script npm

| Script | Comando | Descrizione |
|--------|---------|-------------|
| `npm test` | `vitest run` | Esecuzione singola di tutti i test |
| `npm run test:watch` | `vitest` | Modalità watch per lo sviluppo |
| `npm run test:coverage` | `vitest run --coverage` | Test con report di copertura del codice |
