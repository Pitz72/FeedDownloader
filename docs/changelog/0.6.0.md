# v0.6.0 — Health Check Archivio

> Rilasciato il 26 marzo 2026
> Versione precedente: [v0.5.5](0.5.5.md)

**Versione major feature**: aggiunto il **Health Check Archivio**, uno strumento diagnostico che verifica quanti file scaricati esistono realmente su disco. Tramite un pulsante nelle Impostazioni, l'utente ottiene in pochi secondi un cruscotto con: totale file nel DB, file presenti su disco, file mancanti e spazio totale occupato. In caso di file mancanti, viene mostrata la lista dettagliata (max 5, poi troncata).

---

## ✅ Nuova Feature

### Health Check Archivio

**File modificati/creati:** `shared/types.ts`, `electron/services/LibraryService.ts`, `electron/ipc.ts`, `electron/preload.ts`, `src/vite-env.d.ts`, `src/components/SettingsModal.tsx`, `src/locales/*.json` (8 lingue)

#### Motivazione

Il DB SQLite registra ogni episodio scaricato, ma non garantisce che il file sia ancora fisicamente presente (l'utente potrebbe averlo spostato, rinominato o cancellato manualmente). Il Health Check risolve questa discrepanza senza cancellare nulla: è uno strumento **di sola lettura**.

#### Comportamento

Il Health Check:

1. Recupera tutti i record dall'archivio SQLite (`ArchiveEntry[]`)
2. Per ciascun record ricostruisce il percorso completo: `baseDir / sanitize(podcastTitle) / filename`
3. Verifica l'esistenza del file con `fs.stat()`
4. Accumula `present`, `missing`, `totalSizeBytes` e la lista dei file mancanti
5. Restituisce un oggetto `HealthCheckResult` al renderer

#### Tipo `HealthCheckResult` (shared/types.ts)

```typescript
export interface HealthCheckResult {
    total: number;
    present: number;
    missing: number;
    totalSizeBytes: number;
    missingFiles: { title: string; podcast: string; filename: string }[];
}
```

#### UI in Impostazioni

Nuova sezione "Health Check Archivio" (colore giallo, icona `ShieldCheck`) inserita **dopo** le Archive Stats e **prima** della sezione Data & Portability.

- Pulsante "Avvia Verifica" con spinner animato durante l'esecuzione
- Dopo il completamento: pannello a 3 colonne (Totale / Su disco in verde / Mancanti in rosso se > 0)
- Sotto le colonne: spazio totale occupato su disco (formattato in MB o GB)
- Se ci sono file mancanti: lista dei primi 5 percorsi `podcast / filename`, con "... e altri N" se > 5

#### Gestione percorso base

Se l'utente non ha impostato una cartella download personalizzata, viene usato il default:
```
{documentsDir}/FeedDownloader/downloads
```

#### Edge case

- Voci senza `filename` (es. scaricate con versioni precedenti prive del campo): conteggiate come **mancanti** con filename `(no filename)`
- Errori `fs.stat()` (file non trovato, permessi): conteggiate come mancanti
