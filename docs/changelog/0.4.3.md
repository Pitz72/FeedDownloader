# 🔧 v0.4.3 — "True Extension"

> Data rilascio: 20 marzo 2026

Questa release risolve una **criticità gravissima**: tutti i file scaricati venivano salvati con estensione `.mp3` indipendentemente dal formato reale del file, corrompendo gli archivi contenenti formati come `.m4a`, `.ogg`, `.opus`, `.flac` o `.mp4`.

---

## 🔴 Fix Criticità Gravissima: Estensione `.mp3` Hardcoded

### Il Problema

In `getSafePath()` (originariamente in `ipc.ts`, poi estratta in `electron/utils/getSafePath.ts`), l'estensione del file era fissata a `.mp3`:

```typescript
// ❌ PRIMA (v0.4.0–v0.4.2)
const ext = '.mp3'; // hardcoded — ignora il formato reale
```

Questo significava che:
- Un episodio `.m4a` (Apple Podcast) → salvato come `.m4a.mp3` ❌ (o semplicemente con estensione sbagliata)
- Un file `.ogg` (Opus/Vorbis) → rinominato forzatamente `.mp3`
- Un video podcast `.mp4` → salvato come `.mp3`
- Un PDF allegato nel feed → salvato come `.mp3`

**Conseguenze:**
- I player audio/video non riconoscevano il formato
- I file explorer mostravano l'icona sbagliata
- Strumenti di archiviazione e librerie rilevano file "corrotti"
- L'utente perdeva l'informazione sul formato originale

### La Soluzione: `extractExtension()` con Whitelist Intelligente

Creata la utility `extractExtension()` in `electron/utils/extractExtension.ts` che:

1. **Parsa l'URL** con il costruttore `URL()` nativo
2. **Estrae il pathname** rimuovendo query string (`?token=...`) e fragment (`#t=30`)
3. **Ricava l'estensione** con `path.extname()`, convertendola in lowercase
4. **Verifica contro una whitelist** di 20 estensioni note (audio, video, documenti)
5. **Fallback sicuro** a `.mp3` per URL senza estensione o con estensioni server-side

#### Whitelist delle estensioni supportate

| Tipo | Estensioni |
|------|------------|
| **Audio** | `.mp3`, `.m4a`, `.m4b`, `.aac`, `.ogg`, `.oga`, `.opus`, `.wav`, `.flac`, `.wma`, `.webm` |
| **Video** | `.mp4`, `.m4v`, `.mov`, `.avi`, `.mkv` |
| **Documenti** | `.pdf`, `.epub`, `.zip` |

#### Logica di fallback

| URL di esempio | Estensione estratta |
|----------------|:-------------------:|
| `https://cdn.com/ep42.m4a` | `.m4a` ✅ |
| `https://cdn.com/ep.mp3?token=abc` | `.mp3` ✅ |
| `https://cdn.com/ep.ogg#t=30` | `.ogg` ✅ |
| `https://dts.podtrac.com/redirect.mp3/cdn/ep.mp3` | `.mp3` ✅ |
| `https://cdn.com/ep.MP3` | `.mp3` ✅ (case insensitive) |
| `https://cdn.com/download/12345` | `.mp3` (fallback) |
| `https://cdn.com/stream.php?id=42` | `.mp3` (fallback — `.php` non è nella whitelist) |
| `https://cdn.com/download.aspx?file=ep1` | `.mp3` (fallback) |
| `not-a-valid-url` | `.mp3` (fallback — URL non parsabile) |

### Perché una whitelist e non un passthrough diretto?

I CDN dei podcast spesso usano URL con estensioni server-side:
- `https://tracking-service.com/download.php?feed_id=123&ep_id=456`
- `https://proxy.com/redirect.cgi?target=https://real-cdn.com/ep.mp3`

Senza whitelist, il file verrebbe salvato come `.php` o `.cgi` — peggio di `.mp3` hardcoded. La whitelist garantisce che solo estensioni **realmente audio/video/documento** vengano usate.

## ⚠️ Retrocompatibilità

### File già scaricati con estensione `.mp3`
I file scaricati prima della v0.4.3 rimangono con estensione `.mp3`. La funzionalità "Mostra nella cartella" potrebbe non trovare file pre-0.4.3 se il CDN serviva un formato diverso. Questo è un comportamento atteso: la v0.4.3 corregge solo i **nuovi download**.

### Frontend `SHOW_IN_FOLDER`
Il parametro `enclosureUrl` è **opzionale**: se il frontend non lo invia, il fallback è `.mp3` (retrocompatibile). Per il supporto completo, il componente `EpisodeList.tsx` dovrebbe passare anche l'URL enclosure nella chiamata `window.api.showInFolder()`.
