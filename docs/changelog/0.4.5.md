# 🏷️ v0.4.5 — "Type Safety"

> Data rilascio: 20 marzo 2026

Questa release risolve una **criticità grave**: la tipizzazione `any` pervasiva nel preload, negli handler IPC e nei componenti React, e la duplicazione dei canali IPC tra main e renderer process.

---

## 🟠 Fix Criticità Grave: Tipizzazione `any` Pervasiva

### Il Problema

Il progetto utilizzava `any` in **18 punti** critici:

| File | Occorrenze `any` | Rischio |
|------|:-----------------:|---------|
| `preload.ts` | 9 | Parametri e ritorni non tipizzati → nessun autocomplete, nessun errore compile-time |
| `vite-env.d.ts` | 5 | Tipizzazione Window.api incompleta → errori a runtime invece che a compile-time |
| `ipc.ts` | 2 | `feed: any` nell'handler ADD_FEED → dati arbitrari accettati |
| `Sidebar.tsx` | 1 | `useState<any[]>` → nessun type-check sui dati feed |
| `LibraryService.ts` | 3 | Interfacce locali duplicate → rischio di divergenza |

Inoltre, i canali IPC erano **definiti in due posti diversi**:
- `CH` in `ipc.ts` (main process)
- `IPC_CHANNELS` in `src/types.ts` (renderer process)

Potevano andare fuori sync senza che nessun errore venisse segnalato.

### La Soluzione

#### 1. `shared/types.ts` — Single Source of Truth (🆕)

Creato un file di tipi condiviso al livello root, importabile sia dal main process (`electron/`) che dal renderer (`src/`):

```typescript
// shared/types.ts — importato da entrambi i processi
export interface Episode { ... }
export interface Feed { ... }
export interface FeedEntry { ... }     // ← NUOVO: entry leggera per sidebar
export interface DownloadProgress { ... }
export interface ArchiveEntry { ... }
export interface ArchiveStats { ... }
export interface DownloadRequest { ... } // ← NUOVO: tipizza START_DOWNLOAD
export interface DownloadResult { ... }  // ← NUOVO: risposta download
export const IPC_CHANNELS = { ... } as const; // ← UNICA definizione
```

Nuove interfacce aggiunte:
- **`FeedEntry`**: versione leggera di `Feed` (senza `episodes`), usata per la sidebar e il persistence layer
- **`DownloadRequest`**: tipizza il payload di `START_DOWNLOAD` (era un oggetto inline destrutturato)
- **`DownloadResult`**: tipizza la risposta `{ status: 'queued' }`

#### 2. `preload.ts` — da 9 `any` a Zero

```diff
-parseFeed: (url: string) => ipcRenderer.invoke('parse-feed', url),
-addFeed: (feed: any) => ipcRenderer.invoke('add-feed', feed),
-startDownload: (data: any) => ipcRenderer.invoke('start-download', data),
-onDownloadProgress: (callback: (event: any, data: any) => void) => { ... }
+parseFeed: (url: string): Promise<Feed> => ipcRenderer.invoke(CH.PARSE_FEED, url),
+addFeed: (feed: FeedEntry): Promise<FeedEntry[]> => ipcRenderer.invoke(CH.ADD_FEED, feed),
+startDownload: (data: DownloadRequest): Promise<DownloadResult> => ipcRenderer.invoke(CH.START_DOWNLOAD, data),
+onDownloadProgress: (callback: (event: Electron.IpcRendererEvent, data: DownloadProgress) => void) => { ... }
```

Inoltre, i channel name sono ora usati tramite `CH` (alias di `IPC_CHANNELS`) dal modulo condiviso.

#### 3. `ipc.ts` — Rimossa costante `CH` locale

```diff
-// IPC Channel constants — single source of truth
-const CH = { PARSE_FEED: 'parse-feed', ... } as const;
+import { IPC_CHANNELS as CH } from '../shared/types';
+import type { FeedEntry, DownloadRequest } from '../shared/types';
```

- Eliminata la costante `CH` locale (30 righe di codice rimosse)
- `feed: any` → `feed: FeedEntry`
- Destructuring inline lungo → `DownloadRequest`

#### 4. `LibraryService.ts` — Interfacce locali → Import condivisi

```diff
-interface Feed { url: string; title: string; lastUpdated: string; }
-interface ArchiveEntry { ... }
-interface ArchiveStats { ... }
+import type { FeedEntry, ArchiveEntry, ArchiveStats } from '../../shared/types';
```

20 righe di definizioni duplicate rimosse.

#### 5. `Sidebar.tsx` — `any[]` → `FeedEntry[]`

```diff
+import type { FeedEntry } from '../../shared/types';
-const [feeds, setFeeds] = useState<any[]>([]);
+const [feeds, setFeeds] = useState<FeedEntry[]>([]);
```

#### 6. `vite-env.d.ts` — Dichiarazione globale tipizzata

```diff
-interface Window { api: { parseFeed: (url: string) => Promise<any>; ... } }
+import type { Feed, FeedEntry, ... } from '../shared/types'
+declare global { interface Window { api: { ... } } }
```

Ogni `any` negli event callback sostituito con `Electron.IpcRendererEvent`.

#### 7. `src/types.ts` — Re-export puro

```typescript
// Backward compatibility — renderer components can still import from here
export type { Episode, Feed, FeedEntry, ... } from '../shared/types';
export { IPC_CHANNELS } from '../shared/types';
```
