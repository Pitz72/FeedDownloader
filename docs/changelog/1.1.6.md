## Fix

### D6 — `SettingsModal`: skeleton durante caricamento impostazioni

**Problema:** Il modal si apriva mostrando immediatamente i valori di default (`downloadPath = ''`, `concurrency = 3`, ecc.) mentre `loadSettings()` eseguiva le chiamate IPC asincrone in sequenza. I campi si aggiornavan visibilmente dopo ~50-100ms causando un "flickering" dei valori.

**Fix applicato in:** `src/components/SettingsModal.tsx`

- Aggiunto stato `isLoadingSettings` — `true` durante l'esecuzione di `loadSettings()`
- `loadSettings()` ora ha `setIsLoadingSettings(true)` all'inizio e `setIsLoadingSettings(false)` nel blocco `finally`
- Mentre `isLoadingSettings` è `true`, il pannello destro mostra un overlay skeleton animato (`animate-pulse`) con placeholder per label e campi — 5 righe label + input
- Il contenuto reale (`motion.div` con le sezioni di impostazioni) viene nascosto via `display: none` durante il caricamento, evitando completamente il flickering
