# Changelog v1.3.1

**Data:** 29 maggio 2026

## Security hardening — difesa SSRF completa

Release di sola sicurezza. Nessuna modifica funzionale o di interfaccia: corregge due
vulnerabilità **gravissime** di Server-Side Request Forgery (SSRF) emerse nell'audit di
sicurezza del 29 maggio 2026. L'app scarica da URL di feed ed enclosure controllabili da
terzi, quindi questa era la superficie di rischio più rilevante del programma.

### Vulnerabilità corrette

**1. Redirect HTTP non ri-validati (bypass di `validateUrl`)**

`validateUrl()` veniva eseguito una sola volta sull'URL iniziale, ma `axios` segue i
redirect di default senza ri-controllare la destinazione. Un feed ostile poteva rispondere
`302 → http://127.0.0.1/…` o `→ http://169.254.169.254/…` (metadata endpoint cloud) e la
richiesta seguiva il redirect verso l'host interno. Inoltre il download della **cover art
ID3** (`feedImageUrl`, presa dal feed remoto) avveniva **senza alcuna validazione**.

**2. DNS rebinding + validazione host solo lessicale**

Il controllo era puramente sintattico sulla stringa hostname: un dominio pubblico che
risolve a un IP privato (`attacker.com → 127.0.0.1`) passava il filtro. Mancavano inoltre
i formati IPv4 numerico/ottale/esadecimale (`http://2130706433/`), il range CGNAT
`100.64.0.0/10` e l'IPv4-mapped IPv6.

### Soluzione

* **Nuovo `electron/utils/safeHttp.ts`** — layer HTTP indurito. Installa un `lookup` DNS
  custom sugli agent `http`/`https`: Node risolve l'hostname per **ogni** connessione —
  richiesta iniziale **e ogni hop di redirect** — e la connessione viene rifiutata se l'IP
  risolto è privato/riservato. Questo chiude entrambi i bypass **a livello di socket**,
  che è l'unica difesa reale contro il DNS rebinding.
  * `isPrivateIp()` copre IPv4 (loopback, 10/8, 172.16/12, 192.168/16, link-local, CGNAT
    100.64/10, 0.0.0.0/8, multicast/reserved), IPv6 (`::1`, `::`, ULA `fc00::/7`,
    link-local `fe80::/10`) e IPv4-mapped IPv6 (`::ffff:127.0.0.1`).
  * `SAFE_AXIOS_CONFIG` cabla gli agent sicuri + cap redirect a 5 su tutte le fetch.
* **`validateUrl.ts`** — pre-check lessicale ora delega a `isPrivateIp()` per gli IP
  letterali (copre i formati numerici e IPv4-mapped prima mancanti). Resta la prima linea
  di difesa veloce; la seconda, autoritativa, è il lookup degli agent.
* **`DownloadService.ts`**, **`FeedService.ts`**, **`writeId3Tags.ts`** — tutte e tre le
  chiamate `axios` usano ora `SAFE_AXIOS_CONFIG`. La cover art ID3 viene inoltre validata
  con `validateUrl()` prima del download.
