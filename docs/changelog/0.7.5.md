## Feature

### Supporto Percorsi di Rete (SMB/NFS)

Validazione nativa dei percorsi di rete prima di salvarli come destinazione download.

**Comportamento:**
- Dopo la selezione della cartella (dialog), il percorso viene validato con `fs.access(path, W_OK)`
- Timeout di 8 secondi: se il NAS non risponde entro 8s → toast di errore, percorso non salvato
- Rilevamento automatico percorsi UNC (`\\server\share`, `//server/share`)
- Toast **info** se percorso di rete accessibile: "Percorso di rete rilevato — accesso in scrittura verificato"
- Toast **error** se non raggiungibile (TIMEOUT) o non scrivibile (EPERM/EACCES)

**File aggiunti/modificati:**
- `electron/utils/validateNetworkPath.ts` — NEW: utility con timeout + rilevamento UNC
- `shared/types.ts` — aggiunto `PathValidationResult`, canale `VALIDATE_PATH`
- `electron/ipc.ts` — handler `VALIDATE_PATH` (chiama `validateNetworkPath`)
- `electron/preload.ts` — esposta `validatePath(dirPath)`
- `src/vite-env.d.ts` — aggiunto tipo `validatePath`
- `src/components/SettingsModal.tsx` — `handleChangeFolder` chiama `validatePath` prima di `setDownloadPath`
- `src/locales/*.json` — 3 nuove chiavi (8 lingue): `path_network_detected`, `path_not_writable`, `path_timeout`

### Electron Auto-Update

Integrazione `electron-updater` per aggiornamenti automatici dell'app.

**Comportamento:**
- All'avvio (solo app packaged), controlla aggiornamenti su GitHub Releases dopo 3 secondi
- Il renderer si aggiorna in tempo reale tramite push event `UPDATE_STATUS`
- Tab **Avanzate** → sezione **Aggiornamenti**: mostra versione corrente + pulsante "Controlla Aggiornamenti"
- Stati UI: idle / checking (spinner) / not-available (✓) / available (badge versione) / downloading (progress %) / ready (pulsante "Riavvia e Installa") / error (messaggio)
- Il `latest.yml` con hash SHA-512 viene generato automaticamente da `electron-builder` durante la build
- In modalità dev (`app.isPackaged = false`): il check risponde immediatamente con `not-available`

**Configurazione GitHub Releases** (`package.json` → `build.publish`):
```json
{
  "provider": "github",
  "owner": "GITHUB_OWNER",
  "repo": "FeedDownloader",
  "releaseType": "release"
}
```
Sostituire `GITHUB_OWNER` con il proprio username GitHub prima di pubblicare i release.

**File aggiunti/modificati:**
- `package.json` — aggiunto `electron-updater` in `dependencies`, `build.publish` config, versione → `0.7.5`
- `shared/types.ts` — aggiunto `UpdateStatus` (union type), canali `CHECK_FOR_UPDATE`, `INSTALL_UPDATE`, `UPDATE_STATUS`
- `electron/ipc.ts` — import `autoUpdater`, setup eventi, handlers `CHECK_FOR_UPDATE` e `INSTALL_UPDATE`, auto-check startup

## CI/CD Multipiattaforma

### GitHub Actions — Build & Release

Aggiunto workflow `.github/workflows/build.yml` che compila l'app per Windows, macOS e Linux in parallelo.

**Trigger:**
- Push su `master` → build di verifica con upload degli artifact (nessuna pubblicazione)
- Push di un tag `v*` (es. `v0.7.6`) → build completo + pubblicazione automatica su GitHub Releases
- `workflow_dispatch` → esecuzione manuale dal pannello Actions di GitHub

**Platform matrix:**

| Runner | Output |
|---|---|
| `windows-latest` | `Setup.exe` (NSIS installer) |
| `macos-latest` | `.dmg` + `.zip` |
| `ubuntu-latest` | `.AppImage` + `.deb` |

**Generazione icone automatica nel CI:**
- macOS: `sips` + `iconutil` (strumenti nativi macOS) generano `build/icon.icns` da `public/logo.png`
- Linux: ImageMagick genera `build/icons/{16..512}x{size}.png` da `public/logo.png`
- Windows: `public/icon.ico` già presente nel repo, nessuna generazione necessaria

**File aggiunti/modificati:**
- `.github/workflows/build.yml` — NEW: workflow CI/CD multipiattaforma
- `package.json` — aggiunto script `"release"` (`--publish always`), aggiunto `--publish never` allo script `"build"` locale, `build.publish.owner` impostato a `Pitz72`
- `electron/utils/validateNetworkPath.ts` — `detectNetworkPath()` esteso per riconoscere mount point Linux (`/mnt/`, `/media/`) e macOS (`/Volumes/`) oltre ai percorsi UNC Windows

### Note operative

- Per pubblicare una release: creare un tag `v0.X.Y` e pusharlo (`git tag v0.7.6 && git push origin v0.7.6`). Il workflow si avvia automaticamente, compila su tutti e tre i runner e pubblica i file su GitHub Releases.
- Il `GH_TOKEN` usato nel workflow è il token automatico di GitHub Actions (`secrets.GITHUB_TOKEN`) — nessuna configurazione aggiuntiva necessaria.
- L'auto-updater dell'app (`electron-updater`) scarica gli aggiornamenti dalla stessa GitHub Release prodotta dal workflow.

### Note sulla firma del codice

Il software è distribuito **non firmato** su tutte le piattaforme:

- **Windows:** Al primo avvio, Windows SmartScreen mostra l'avviso "Autore sconosciuto". Procedura: **Ulteriori informazioni → Esegui comunque**. Il software è sicuro.
- **macOS:** Il pacchetto non è firmato con un certificato Apple Developer (code signing). Al primo avvio, Gatekeeper blocca l'app. Procedura: clic destro → **Apri**, oppure **Impostazioni di sistema → Privacy e sicurezza → Apri comunque**.
- **Linux:** `.AppImage` e `.deb` non richiedono firma. Nessun avviso atteso.
