# 🧹 v0.4.9 — "Lieve Cleanup"

> Data rilascio: 21 marzo 2026

Questa release risolve le **7 criticità lievi** identificate nel report di analisi del codice (v0.4.8), completando la prima fase di bonifica del progetto. Nessuna modifica funzionale, solo miglioramenti di qualità, sicurezza e correttezza del codice.

## 🟢 Fix 1: `<img>` senza attributo `alt` (`src/components/Sidebar.tsx`)

### Il Problema
Le copertine podcast nella Sidebar erano renderizzate senza attributo `alt`:

```tsx
// ❌ PRIMA
<img src={imageUrl} className="w-full h-full object-cover" />
```

Questo violava le linee guida di accessibilità WCAG (a11y): screen reader e strumenti assistivi non avevano descrizione dell'immagine.

### La Soluzione

```tsx
// ✅ DOPO
<img src={imageUrl} className="w-full h-full object-cover" alt={feed.title || ''} />
```

Il testo alternativo usa il titolo del podcast. Se assente, stringa vuota (immagine decorativa).

## 🟢 Fix 2: Import diretto di `package.json` nel Renderer (`src/components/Sidebar.tsx`)

### Il Problema
La Sidebar importava l'intero `package.json` per leggere solo `version`:

```typescript
// ❌ PRIMA — espone dipendenze, scripts, config nel bundle client
import pkg from '../../package.json';
// ...
<p className="text-xs text-center text-gray-600">v{pkg.version}</p>
```

Sebbene Vite tree-shake gli import JSON, il bundler poteva includere metadati non necessari nel bundle del Renderer.

### La Soluzione: costante `__APP_VERSION__` iniettata a build-time

**`vite.config.ts`** — lettura della versione da `package.json` lato Node.js e iniezione tramite `define`:

```typescript
import { readFileSync } from 'node:fs'

const { version } = JSON.parse(
  readFileSync(new URL('./package.json', import.meta.url), 'utf-8')
)

export default defineConfig({
  define: {
    __APP_VERSION__: JSON.stringify(version),
  },
  // ...
})
```

**`src/vite-env.d.ts`** — dichiarazione globale TypeScript:

```typescript
declare global {
    const __APP_VERSION__: string;
    // ...
}
```

**`src/components/Sidebar.tsx`** — rimosso import, usata la costante globale:

```diff
-import pkg from '../../package.json';
// ...
-<p className="text-xs text-center text-gray-600">v{pkg.version}</p>
+<p className="text-xs text-center text-gray-600">v{__APP_VERSION__}</p>
```

**Benefici:**
- Solo la stringa versione (es. `"0.4.9"`) entra nel bundle — nessun metadato del progetto esposto.
- Compatibile con qualsiasi build tool, non dipende dal comportamento di tree-shaking di Vite.
- Tipo inferito correttamente da TypeScript.

## 🟢 Fix 3: Codice di debug residuo in `electron/main.ts`

### Il Problema
Un blocco di test Electron mai rimosso inviava un messaggio inutilizzato al Renderer ad ogni caricamento della pagina:

```typescript
// ❌ PRIMA — codice di test residuo
// Test active push message to Renderer-process.
win.webContents.on('did-finish-load', () => {
    win?.webContents.send('main-process-message', (new Date).toLocaleString())
})
```

Questo generava un evento IPC non gestito ad ogni avvio, con potenziale per warning nel Renderer se un listener veniva registrato (o silenziosamente ignorato se non lo era).

### La Soluzione

Rimosso l'intero blocco. Il commento descrittivo e il listener sono stati eliminati.

## 🟢 Fix 4: `isOnline` statico → hook reattivo `useOnlineStatus`

### Il Problema
In `EpisodeList.tsx`, lo stato di connessione era un valore statico valutato una sola volta al render:

```typescript
// ❌ PRIMA — snapshot non reattivo
const isOnline = navigator.onLine;
```

Se l'utente perdeva la connessione mentre il componente era già montato, il bottone "Scarica" rimaneva abilitato. Se la recuperava, rimaneva disabilitato. Nessun aggiornamento senza un re-render completo del componente.

### La Soluzione: hook `useOnlineStatus`

**Nuovo file `src/hooks/useOnlineStatus.ts`:**

```typescript
import { useEffect, useState } from 'react';

export function useOnlineStatus(): boolean {
    const [isOnline, setIsOnline] = useState(navigator.onLine);

    useEffect(() => {
        const handleOnline = () => setIsOnline(true);
        const handleOffline = () => setIsOnline(false);

        window.addEventListener('online', handleOnline);
        window.addEventListener('offline', handleOffline);

        return () => {
            window.removeEventListener('online', handleOnline);
            window.removeEventListener('offline', handleOffline);
        };
    }, []);

    return isOnline;
}
```

**`src/components/EpisodeList.tsx`:**

```diff
+import { useOnlineStatus } from '../hooks/useOnlineStatus';
// ...
-const isOnline = navigator.onLine;
+const isOnline = useOnlineStatus();
```

**Comportamento:** Il componente si aggiorna automaticamente in risposta agli eventi `online`/`offline` del browser, abilitando/disabilitando i pulsanti di download in tempo reale.

## 🟢 Fix 5: `downloads` Record senza cleanup — memory leak (`src/store/useStore.ts`)

### Il Problema
L'oggetto `downloads: Record<string, DownloadProgress>` nello store Zustand cresceva indefinitamente. Ogni download aggiungeva una entry che non veniva mai rimossa:

```typescript
// ❌ PRIMA — nessun cleanup, la mappa cresce per sempre
updateDownload: (progress) => set((state) => ({
    downloads: {
        ...state.downloads,
        [progress.url]: { ...state.downloads[progress.url], ...progress }
    }
})),
```

In una sessione di lavoro con centinaia di episodi scaricati, il Record accumulava centinaia di entry in RAM senza mai liberarle.

### La Soluzione: cleanup ritardato di 2 secondi

```typescript
// ✅ DOPO
updateDownload: (progress) => {
    set((state) => ({
        downloads: {
            ...state.downloads,
            [progress.url]: { ...state.downloads[progress.url], ...progress }
        }
    }));
    // Schedule cleanup after 2s to let the UI render the final state
    if (progress.completed || progress.error) {
        setTimeout(() => set((state) => {
            const updated = { ...state.downloads };
            delete updated[progress.url];
            return { downloads: updated };
        }), 2000);
    }
},
```

**Perché 2 secondi di ritardo:**
- Al completamento, il Renderer riceve anche l'evento push `DOWNLOADS_UPDATED` che aggiorna `downloadedGuids`.
- Il componente `EpisodeList` usa `downloadedGuids.includes(guid)` come fonte primaria dello stato "scaricato".
- 2 secondi garantiscono che la UI abbia già renderizzato lo stato finale prima che la entry venga rimossa dallo store.
- Dopo la rimozione, `isCompleted` rimane `true` grazie a `downloadedGuids`, senza alcun flash visivo.

## 🟢 Fix 6: ESLint non integrato nel build (`package.json`)

### Il Problema
ESLint era configurato e disponibile tramite `npm run lint`, ma non veniva eseguito durante il build. Errori di linting non bloccavano la compilazione, rendendo possibile distribuire codice con warning o errori ignorati:

```json
// ❌ PRIMA
"build": "tsc && vite build && electron-builder"
```

### La Soluzione

```json
// ✅ DOPO
"build": "npm run lint && tsc && vite build && electron-builder"
```

Il lint viene eseguito come primo step. Se ESLint trova errori (con `--max-warnings 0`), il build si interrompe prima di raggiungere `tsc` o `electron-builder`.

## 🟢 Fix 7: `dist-electron/` non in `.gitignore`

### Il Problema
La directory `dist-electron/` (output compilato del Main process Electron, generato da Vite) non era nel `.gitignore`. Rischio concreto di committare accidentalmente artefatti binari compilati nel repository.

### La Soluzione

```diff
 node_modules
 dist
+dist-electron
 dist-ssr
 *.local
```
