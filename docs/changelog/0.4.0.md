# 🚀 v0.4.0 — "Architettura Solida"

> Data rilascio: 24 febbraio 2026

Questa release rappresenta il più grande aggiornamento singolo dalla nascita del progetto. Introduce miglioramenti architetturali profondi, nuove funzionalità per l'utente, e una riorganizzazione completa della documentazione. Ogni criticità identificata nel report di analisi v0.3.3 è stata risolta.

---

## 🔴 Fix Criticità Gravi

### 1. Eliminazione completa del Polling IPC
- **Prima:** `EpisodeList.tsx` e `Sidebar.tsx` usavano `setInterval` (ogni 2-3 secondi) per interrogare il main process → spreco CPU costante
- **Dopo:** Implementati **push events** dal main process al renderer:
  - `feeds-updated` → aggiorna la lista feed in tempo reale
  - `downloads-updated` → aggiorna lo stato download istantaneamente
  - `batch-completed` → segnale di completamento batch
- **File modificati:** `ipc.ts`, `preload.ts`, `EpisodeList.tsx`, `Sidebar.tsx`

### 2. IPC_CHANNELS centralizzato — Zero stringhe magiche
- **Prima:** Solo 10 canali su 22 erano definiti come costanti, i restanti usavano stringhe literali ("magic strings")
- **Dopo:** Tutte le 25 costanti (incluse le 3 nuove) sono definite nell'oggetto `CH` in `ipc.ts` e separatamente in `src/types.ts` per il frontend
- **Rischio eliminato:** Refusi o disallineamenti fra `ipcMain.handle()` e `ipcRenderer.invoke()` vengono ora intercettati a livello di tipo

### 3. Interfaccia Episode tipizzata — Eliminazione di `any`
- **Prima:** `episodes: any[]` nello store Zustand, feed con tipo `any` nella Sidebar, episodi senza tipo nei componenti
- **Dopo:** Creato `src/types.ts` con interfacce `Episode`, `Feed`, `DownloadProgress`, `ArchiveStats`, `ArchiveEntry`
- **Store** aggiornato per importare i tipi
- **Componenti** aggiornati per usare `Episode` invece di `any`

## 🟡 Fix Criticità Medie

### 4. Stringhe hardcoded in italiano → i18n completo
- **Prima:** `UrlInput.tsx` conteneva 4 messaggi di errore in italiano, incollati direttamente nel codice
- **Dopo:** Tutte le stringhe usano `t()` di i18next con le chiavi: `toast.parse_error`, `toast.invalid_feed`, `toast.network_error`, `toast.feed_not_found`
- **Aggiornati tutti e 8 i file locale** con le nuove chiavi

### 5. Rimosso @ts-ignore residuo
- `Sidebar.tsx:48` — Il `@ts-ignore` su `setCurrentFeed(null)` era inutile (il tipo accetta già `null`). Rimosso.

### 6. Caching locale nella Sidebar
- **Prima:** Ogni click su un feed nella sidebar effettuava una chiamata HTTP per ri-parsare il feed RSS
- **Dopo:** Se il feed selezionato è lo stesso già caricato, non viene effettuata alcuna richiesta

### 7. Gestione Content-Length assente (NaN% fix)
- **Prima:** Se il server non restituiva `Content-Length`, la barra di progresso mostrava `NaN%`
- **Dopo:** Se `total` è 0 o assente, viene mostrato un indicatore di caricamento testuale invece della percentuale

### 8. Pulizia codice morto
- Rimosso commento duplicato in `preload.ts` ("Expose some API...")
- Rimosso commento duplicato in `main.ts` ("Show window when ready to avoid flickering")
- Rimosso codice commentato in `UrlInput.tsx`
- Rimossa dichiarazione fantasma `Window.ipcRenderer` da `electron-env.d.ts`
- Rimossa interfaccia fantasma `Window.electron` da `vite-env.d.ts`

## 🟢 Fix Criticità Minori

### 9. Icone semantiche per Import/Export
- **Prima:** Tutto usava `FolderOpen` indiscriminatamente
- **Dopo:** Import OPML → `Upload` (verde), Export OPML → `Download` (blu), Export CSV → `FileSpreadsheet` (viola)

### 10. ConfirmModal al posto di confirm() nativo
- **Prima:** `confirm()` nativo del browser in 3 punti (EpisodeList download all, Sidebar remove, EpisodeList reset)
- **Dopo:** Creato componente `ConfirmModal.tsx` riutilizzabile con animazione, backdrop blur, varianti (danger/warning/info)
- **Integrato in:** `EpisodeList.tsx`, `Sidebar.tsx`

### 11. Rimosso `reproduce_feed.ts`
- File di debug/test nella root del progetto. Eliminato.

### 12. Noise SVG localizzato
- **Prima:** `App.tsx` e `IntroScreen.tsx` caricavano un SVG da `grainy-gradients.vercel.app` (CDN esterno)
- **Dopo:** Creato `public/noise.svg` locale. L'app funziona ora correttamente anche offline.

### 13. README.md sostituito
- **Prima:** Template Vite di default con istruzioni generiche
- **Dopo:** README completo con overview del progetto, feature principali, stack tecnologico, indice multi-lingua e quick start

## ✨ Nuove Funzionalità (Evoluzioni a Breve Termine)

### 14. Download paralleli configurabili
- Nuovo selettore in **Impostazioni → Archiviazione** con tre opzioni: **1**, **3**, **5** download simultanei
- L'impostazione è persistente (salvata in `electron-store`)
- Implementato in: `QueueService.setConcurrency()`, `LibraryService.get/setConcurrency()`, `SettingsModal.tsx`

### 15. Filtri per data nella lista episodi
- Nuovo pulsante **"Filtro Data"** nella toolbar degli episodi
- Apre un pannello con date picker **Da** / **A**
- Filtra gli episodi visibili per intervallo di pubblicazione
- Integrazione con il filtro di ricerca testuale esistente
- Pulsante "Pulisci" per resettare il filtro

### 16. Notifica OS al completamento batch
- Al termine di un download di massa, viene mostrata una **notifica nativa del sistema operativo** (Windows Toast / macOS Notification Center)
- Titolo: "Runtime FeedDownloader Pro"
- Corpo: "Download completato: X file scaricati."
- Implementato con `Electron.Notification`

### 17. Statistiche Archivio (Dashboard)
- Nuova sezione **"Statistiche Archivio"** nelle Impostazioni
- Mostra:
  - **Numero totale file scaricati**
  - **Numero podcast distinti**
  - **Periodo archivio** (data più vecchia — data più recente)
- I dati vengono calcolati dalle entry dell'archivio in `electron-store`

### 18. GlobalProgressBar migliorata
- Al completamento del batch, la barra mostra **"Completato!"** con icona verde
- Pulsante di chiusura per dismissare la notifica
- La barra diventa verde al 100%
