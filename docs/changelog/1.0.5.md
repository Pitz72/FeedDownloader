## Fix

### C1 — `showInFolder` ora applica il naming template e l'estensione corretta

**Problema:** Il pulsante "Apri cartella" per gli episodi scaricati ricostruiva il percorso del file usando il titolo grezzo dell'episodio, ignorando completamente il naming template configurato in Impostazioni. Se il template era diverso da `{title}` (ad esempio `{date} - {title}`), la funzione cercava un file con nome sbagliato e apriva la cartella senza selezionare nulla. Inoltre l'estensione era hardcoded a `.mp3` indipendentemente dal formato reale del file.

**Fix applicato in:**
- `electron/ipc.ts` — handler `SHOW_IN_FOLDER`: aggiunto parametro `pubDate`, applicato `applyTemplate(namingTemplate, ...)` prima di `getSafePath`, esattamente come in `START_DOWNLOAD`
- `electron/preload.ts` — aggiunto `pubDate?: string` alla firma di `showInFolder`
- `src/vite-env.d.ts` — aggiornata la dichiarazione di tipo `window.api.showInFolder`
- `src/components/EpisodeList.tsx` — la chiamata a `showInFolder` ora passa `url` (enclosure URL per l'estensione corretta) e `episode.pubDate || episode.isoDate`

---

### C2 — Collision check: nessuna sovrascrittura silenziosa di file con titolo identico

**Problema:** Se due episodi avevano lo stesso titolo dopo sanitizzazione del filesystem (ad esempio titoli molto corti, numerici o con solo punteggiatura), il secondo download sovrascriveva silenziosamente il primo file senza alcun avviso.

**Fix applicato in:**
- `electron/ipc.ts` — handler `START_DOWNLOAD`: dopo il calcolo di `baseSafePath`, viene verificata l'esistenza del file di destinazione. Se presente, si aggiunge progressivamente il suffisso `_2`, `_3`, ecc. fino a trovare un nome libero.

```
episodio.mp3        → già esiste
episodio_2.mp3      → già esiste
episodio_3.mp3      → libero ✓
```
