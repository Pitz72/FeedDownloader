# Changelog v1.3.8

**Data:** 29 maggio 2026

## Criticità medie — performance e configurazione (M5–M7)

Secondo blocco delle criticità **medie** dell'audit del 29 maggio 2026.

### M5 — `ArchiveView` ricaricava tutto l'archivio ad ogni download

Durante un batch il main process emette `downloads-updated` dopo **ogni** file
completato. La vista Archivio ri-fetchava l'intero archivio ad ogni evento — costoso su
librerie grandi durante batch lunghi.

* I reload sono ora **coalizzati** dietro un debounce di 600 ms: una raffica di
  completamenti produce un singolo ricaricamento. Timer ripulito allo smontaggio.

### M6 — Re-render globale da `useStore(s => s)`

`Sidebar` e `DownloadPanel` sottoscrivevano l'**intero** store (`s => s`): poiché il
riferimento dello stato cambia ad ogni `set`, entrambi i componenti si ri-renderizzavano
ad ogni mutazione, anche del tutto scorrelata (progresso download, coda, batch…).

* Sostituiti con **selettori per singola slice**: ogni componente si ri-renderizza solo
  quando cambia lo stato che usa davvero.

### M7 — ESLint env e tsconfig DOM applicati al main process

Il main process (Node) era lintato con `env: browser` e type-checkato con le librerie
**DOM**: globali come `document`/`window` non davano errore nel codice del processo
principale.

* **ESLint**: override per `electron/**` e `shared/**` con `env: { node: true, browser:
  false }`.
* **tsconfig**: nuovo `tsconfig.electron.json` con `lib: ["ES2020"]` (senza DOM) per il
  main process; il `tsconfig.json` radice ora include `src` + `electron/preload.ts`
  (il preload gira nel mondo isolato del renderer e usa il DOM, quindi resta sotto le
  lib DOM). Gli script `build`/`release` eseguono entrambi i type-check
  (`tsc && tsc -p tsconfig.electron.json`). Verificato: il main compila senza DOM.
