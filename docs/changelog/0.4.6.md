# 🗄️ v0.4.6 — "SQLite Core"

> Data rilascio: 20 marzo 2026

Questa release risolve una **criticità grave di scalabilità**: l'uso di `electron-store` (file JSON) come database veniva sostituito da **SQLite** (via `better-sqlite3`), eliminando i problemi di performance con archivi di grandi dimensioni.

---

## 🟠 Fix Criticità Grave: electron-store come Database

### Il Problema

`electron-store` salva tutti i dati in un **singolo file JSON** (`config.json`):

```json
{
    "feeds": [ ... array di tutti i feed ... ],
    "downloads": [ ... array di tutti i GUID ... ],
    "archive": [ ... array di tutte le entry ... ],
    "concurrency": 3,
    "downloadPath": "/path/to/downloads"
}
```

**Problemi di scalabilità:**

| Operazione | Complessità con JSON | Con SQLite |
|------------|:-------------------:|:----------:|
| Aggiungere 1 feed | O(n) — legge tutto, pusha, riscrive tutto | O(1) — INSERT |
| Cercare se un GUID è scaricato | O(n) — `array.includes()` su tutto | O(1) — INDEX |
| Contare podcast distinti | O(n) — `new Set(array.map())` | O(1) — COUNT DISTINCT |
| Trovare date min/max | O(n log n) — sort + accesso | O(1) — MIN/MAX |
| Rimuovere 1 download + archivio | O(n) × 2 — filter + riscrittura | O(1) — DELETE |

Con 1000+ episodi scaricati, ogni operazione riscriveva un file JSON da diversi MB su disco.

### La Soluzione: `DatabaseService` con SQLite

#### Schema del database

```sql
CREATE TABLE feeds (
    url         TEXT PRIMARY KEY,
    title       TEXT NOT NULL DEFAULT '',
    image       TEXT,
    lastUpdated TEXT
);

CREATE TABLE downloads (
    guid TEXT PRIMARY KEY
);

CREATE TABLE archive (
    guid          TEXT PRIMARY KEY,
    podcastTitle  TEXT NOT NULL DEFAULT '',
    title         TEXT NOT NULL DEFAULT '',
    pubDate       TEXT NOT NULL DEFAULT '',
    downloadedAt  TEXT NOT NULL DEFAULT '',
    filename      TEXT
);

CREATE TABLE settings (
    key   TEXT PRIMARY KEY,
    value TEXT
);
```

#### Vantaggi concreti

| Feature | electron-store | SQLite (better-sqlite3) |
|---------|:--------------:|:-----------------------:|
| Formato | JSON su disco | Database binario |
| Concurrency | Blocco file intero | WAL mode (letture parallele) |
| Duplicati | `array.find()` manuale | `INSERT OR IGNORE` |
| Transazioni | ❌ | ✅ (atomiche) |
| Ricerca | O(n) scan | O(1) indice |
| Statistiche | O(n) in JS | `COUNT`/`MIN`/`MAX` SQL |
| Scalabilità | Degrada > 500 entry | Milioni di entry |

## 🏗️ Architettura

```
ipc.ts
  └── LibraryService (logica di business: OPML, validazione)
         └── DatabaseService (CRUD SQLite puro)
```

### `DatabaseService` — Nuovo (🆕)

Responsabile di:
- Inizializzazione schema (con `CREATE TABLE IF NOT EXISTS`)
- WAL mode + foreign keys
- Operazioni CRUD atomiche (tutte le query sono prepared statements)
- Transazioni per operazioni composite (`removeDownloadedEpisode` = DELETE download + DELETE archive)
- Settings key-value per configurazione (concurrency, downloadPath)

**Path del database:** `{userData}/feeddownloader.sqlite`

### `LibraryService` — Riscritto

Ora è un **thin delegate** verso `DatabaseService`:
- CRUD feeds/downloads/archive → delegate diretto
- OPML import/export → logica di parsing resta qui (non è CRUD puro)
- Accetta `DatabaseService` iniettabile nel costruttore per testabilità

```typescript
// v0.4.5: LibraryService usava electron-store direttamente
export class LibraryService {
    private store = new Store(); // ❌ JSON file
}

// v0.4.6: LibraryService delega a DatabaseService
export class LibraryService {
    private db: DatabaseService; // ✅ SQLite
    constructor(db?: DatabaseService) {
        this.db = db || new DatabaseService();
    }
}
```

### Suite `LibraryService.test.ts` — Riscritto (26 test)

I test **non mockano più `electron-store`**. Viene iniettato un `DatabaseService` con SQLite in-memory:

```typescript
beforeEach(() => {

});
```

Questo rende i test più realistici: usano un database **vero** (solo in-memory).

## ⚠️ Note sulla Migrazione

### Dati esistenti
I dati precedenti (salvati in `electron-store` / `config.json`) **non vengono migrati automaticamente**. Al primo avvio con v0.4.6, il database SQLite sarà vuoto. L'utente dovrà re-importare i feed via OPML se necessario.

### Retrocompatibilità
`electron-store` resta installato come dipendenza nel `package.json` ma non è più importato da nessun servizio. Può essere rimosso in una futura release di pulizia.

### Bonus: `any` eliminato
Il metodo `importOPML` conteneva un `traverse(node: any)` — ora tipizzato con interfaccia locale `OPMLNode`:

```typescript
interface OPMLNode {
    xmlUrl?: string;
    text?: string;
    title?: string;
    outline?: OPMLNode | OPMLNode[];
}
```
