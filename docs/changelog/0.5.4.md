# v0.5.4 — Template Naming

> Rilasciato il 26 marzo 2026
> Versione precedente: [v0.5.3](0.5.3.md)

Aggiunto il supporto per un **template personalizzabile del nome file** degli episodi scaricati. L'utente può ora configurare un pattern con token come `{title}`, `{podcast}`, `{date}`, ecc. per controllare come vengono nominati i file scaricati.

---

## Nuova Feature

### Template Nome File (File Naming Template)

**File modificati:** `electron/utils/applyTemplate.ts` (nuovo), `electron/services/DatabaseService.ts`, `electron/services/LibraryService.ts`, `shared/types.ts`, `electron/preload.ts`, `electron/ipc.ts`, `src/components/SettingsModal.tsx`, `src/vite-env.d.ts`, `src/locales/*.json` (8 lingue)

#### Token supportati

| Token | Descrizione |
|-------|-------------|
| `{title}` | Titolo dell'episodio |
| `{podcast}` | Nome del podcast |
| `{date}` | Data di pubblicazione (YYYY-MM-DD) |
| `{year}` | Anno (4 cifre) |
| `{month}` | Mese (2 cifre, zero-padded) |
| `{day}` | Giorno (2 cifre, zero-padded) |

Se la data di pubblicazione non è disponibile o non è valida, i token relativi alla data vengono sostituiti con `unknown`.

#### Default

Il template di default è `{title}`, che preserva il comportamento precedente.

#### UI (SettingsModal)

Nella sezione **Storage** delle impostazioni, dopo i pulsanti di concorrenza, è stata aggiunta una nuova sotto-sezione con:
- Campo di testo monospace per inserire il template
- Salvataggio automatico `onBlur`
- Riga di aiuto con i token disponibili
- Anteprima live con valori di esempio (`My Podcast`, `Episode Title`, `2024-03-15`)

#### Implementazione

Il template viene applicato in `electron/ipc.ts` all'interno dell'handler `START_DOWNLOAD`, prima di costruire il percorso file:

```typescript
const namingTemplate = libraryService.getNamingTemplate();
const resolvedName = applyTemplate(namingTemplate, {
    title,
    podcast: podcastTitle,
    pubDate: pubDate,
});
const targetFile = getSafePath(baseDir, podcastTitle, resolvedName, ext);
```

La funzione `applyTemplate` usa `.replace()` con regex case-insensitive (`/\{title\}/gi`) per sostituire i token. Il nome risolto passa poi per `getSafePath` che continua a gestire la sanitizzazione dei caratteri non validi per il filesystem.
